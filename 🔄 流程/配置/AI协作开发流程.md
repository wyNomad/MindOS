# 🤖 AI 协作开发流程

## 目标

- 固化当前常用的人机协作开发方式。
- 明确本机终端、远程连接与不同 AI Agent 的分工。
- 让后续进入项目时可以快速复用同一套工作节奏。

## 适用场景

- 在香橙派 5 Plus 的 Ubuntu 22.04 环境中进行日常开发。
- 处理 ROS 2、嵌入式 Linux、机器人相关工程。
- 需要在 Claude Code、Codex、Trae / Trae AI 之间协同完成理解、建议与代码修改。

## 环境前提

- 主开发环境：香橙派 5 Plus + Ubuntu 22.04。
- 本机终端可用：Claude Code、Codex。
- 远程访问可用：笔记本 + MobaXterm + Trae。
- 项目代码已放在目标开发目录中，可被终端 Agent 或远程编辑器读取。

## 分工原则

1. 主环境默认是香橙派本机。
2. 需要远程操作时，使用笔记本通过 MobaXterm 或 Trae 连接香橙派。
3. 需要理解工程结构、阅读特定项目上下文、给出整体建议时，优先使用 Claude Code + Serena。
4. 需要推进模块化实现、修改具体代码、落地局部功能时，优先使用 Codex。
5. 需要在远程 GUI 编辑器环境中快速查看、编写或配合其他 AI 时，可使用 Trae 与其内置 AI。

## 共享记忆原则

1. 临时上下文可以存在当前对话、Claude Code 会话或 Serena 的工程记录里。
2. 需要跨会话、跨 Agent 复用的信息，应优先沉淀到 MindOS。
3. MindOS 负责保存值得长期保留的共享大脑，而不是把所有细碎过程都塞进 Agent 的隐式记忆。
4. 对项目真正重要的内容，优先写入可审阅的本地文档，而不是只留在聊天记录里。
5. Serena 的记录可继续用于工程理解，但长期协作所需的信息应尽量回收到 MindOS 中。

## 标准步骤

1. 明确当前任务。
   - 先用自然语言说明背景、现状、目标与限制条件。
   - 如果任务较大，先拆成若干子目标。

2. 确认工作环境。
   - 如果在香橙派本机终端直接处理，优先使用 Claude Code / Codex。
   - 如果在笔记本上远程处理，先通过 MobaXterm 或 Trae 连到香橙派。

3. 做工程理解。
   - 让 Claude Code 结合 Serena 读取目标工程。
   - 输出当前结构理解、问题定位、风险点和实现建议。

4. 确定执行拆分。
   - 把任务拆成可执行的小步骤。
   - 明确哪些部分属于架构理解，哪些部分属于模块实现。

5. 执行代码修改。
   - 结构理解、整体建议、方案比较阶段：以 Claude Code 为主。
   - 模块化实现、具体补丁、代码落地阶段：以 Codex 为主。
   - 远程编辑器中需要快速人工介入时：使用 Trae 配合完成查看与调整。

6. 遇到不懂的点及时追问。
   - 对概念、报错、工程结构或方案不确定时，先向 AI 追问澄清。
   - 避免在理解不完整时直接推进大量修改。

7. 回收结果。
   - 检查修改是否符合目标。
   - 记录关键决策、踩坑和后续待办。
   - 如有可复用经验，沉淀到 MindOS 对应文档。

8. 会话结束前做一次轻量收尾。
   - 如果当天已完成较多工作，关闭对话前先做 3-5 分钟整理。
   - 优先沉淀“明天继续时还需要知道什么”。

## 收尾沉淀规则

适用时机：
- 一天工作结束准备休息
- 一段对话即将关闭
- 已完成一个阶段任务或排错任务
- 明显产生了新的决策、经验、状态变化

优先记录的内容：
- 今天做了什么
- 当前做到哪一步
- 还有什么没完成
- 为什么这么做
- 遇到了什么坑、如何解决
- 下次继续时最先要看什么

推荐落点：
- 项目背景、当前状态、里程碑：写入 `🚀 项目/`
- 学习过程、实验记录、排错过程：写入 `📝 笔记/`
- 可复用做法、稳定步骤：写入 `🔄 流程/`
- 长期目标或当前阶段变化：同步到 `👤 画像/🎯 聚焦.md`
- 长期稳定偏好变化：同步到 `👤 画像/⚙️ 偏好.md`

最小收尾模板：

```text
今天完成：
当前进度：
关键决策：
踩坑/问题：
下次继续先做：
```

执行要求：
1. 不要求每天写长文，短记录也可以。
2. 优先记录以后会忘、但下次继续很关键的信息。
3. 若信息仅对当前工程局部有用，可先写项目记录；若有长期复用价值，再提炼成 SOP。
4. 目标是减少对单个 Agent 会话记忆的依赖，让我、Claude Code、Trae AI 在后续都能从 MindOS 接上上下文。

## 推荐提问模板

- 当前情况：我现在在做什么，卡在哪。
- 目标：我希望最后达到什么结果。
- 范围：请先读哪些目录或文件。
- 方式：先分析再改，还是直接改。

示例：

```text
先读取我的 ROS2 工程，帮我理解这个模块的结构和问题，再给出修改建议。
```

```text
这是一个模块化改动，请你直接作为主力修改代码，但先告诉我风险点。
```

## 验收标准

- 能根据任务类型快速判断使用 Claude Code、Codex 或 Trae。
- 能先理解工程再修改，而不是脱离上下文直接动手。
- 大任务可以被拆分成清晰的小步骤执行。
- 关键经验可继续沉淀回 MindOS。
- 结束会话时，重要上下文不会只留在聊天记录或局部工具记忆里。
