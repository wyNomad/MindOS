# MindOS 知识库同步与强制恢复流程

## 适用场景

- 本地新初始化后的仓库历史与云端主分支无关。
- `mindos sync now` 或等效同步流程失败，且问题本质是本地历史无法与远端对齐。
- 已确认远端 `origin/main` 是当前应当保留的权威内容。

## 风险提示

- `git reset --hard origin/main` 会直接丢弃本地当前工作树与提交历史差异。
- 若本地仍有未备份内容，先另存或新建分支，不要直接执行强制恢复。
- 若不确定云端是否为最新正确版本，先核对后再操作。

## 最小步骤

1. 确认远端仓库和分支配置正确。
2. 拉取远端最新状态。

```bash
git fetch origin
```

3. 检查本地是否存在需要保留的未提交改动，并先完成备份。
4. 强制将本地对齐到远端主分支。

```bash
git reset --hard origin/main
```

5. 重新检查核心目录与关键文档是否恢复。
6. 触发一次同步，或等待自动同步机制恢复正常。
7. 将这次处理结果记录到 `CHANGELOG.md`，并把临时笔记按分区原则归位。

## 验证清单

- `👤 画像/`、`📝 笔记/`、`🔄 流程/`、`🚀 项目/` 等核心目录已恢复。
- 关键项目文档和流程文档已重新出现。
- 自动同步机制恢复正常。
- Agent 仍能通过既有 MCP 或本地挂载方式访问该知识库。

## 历史验证

- 旧设备仓库曾通过强制对齐重新恢复云端内容。
- 该流程适合在确认远端为权威版本时使用，不适合处理未备份的本地新内容。
