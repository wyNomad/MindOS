# 01 筑基：从环境隔离到物理执行闭环

在机器人工程中，环境搭建并非简单的软件安装，而是构建一个可预测、可复现、且高度隔离的开发平台。地基的稳固程度直接决定了上层算法的上限。如果地基不稳，后续所有复杂的 ROS 2 节点通信都可能在无法预料的系统层级崩溃。

## 1. 基础设施：开发环境的构建

刚装好的 Ubuntu 22.04 虚拟机处于初始状态，首要任务是打通其与外部物理世界的连接，并建立一套稳健的开发流程。

- **网络配置**：通过网络桥接模式（Bridge Mode），让虚拟机在局域网内获得独立的物理 IP。这不只是为了操作便利，更是为了让基于 DDS 协议的分布式节点通信能够实现真正的点对点连通。
- **环境隔离**：采用 Miniconda 实现多版本 Python 环境的共存。系统原生环境确保 ROS 2 Jazzy 的核心稳定性，而 Conda 沙盒则用于隔离那些依赖冲突严重的 AI 推理库。
- **工程化思维**：引入 Docker 封装具有复杂 CUDA 依赖的工具链，并建立严谨的 Git 工作流。每一次参数微调与 Bug 修复，都成为项目进化的可追溯日志。

## 2. 算力演进：生存驱动的硬件迭代

随着视觉 SLAM 与多模态融合算法的加入，原有的树莓派 4B 在处理高频点云流时显得捉襟见肘。当 CPU 占用率拉满导致控制频率大幅抖动时，系统会面临严重的延迟风险。于是，核心算力经历了必要的迭代，转向 **香橙派 5 Plus（RK3588）**。这不仅是主频的提升，更是为了给上层算法留出足够的计算余量，确保整个系统的实时性。

## 3. 物理执行：从数学公式到电机的闭环响应

任何高层智能的基石，都是一个具备精确响应能力的物理底盘。

针对本项目的三角形全向轮底盘，建立了严谨的正逆运动学模型。通过运动学方程，系统能够实现机器人整体速度向量（vx、vy、ω）与 3 个独立电机转速之间的双向实时解析。

- **电控逻辑设计**：在 STM32 侧，设计了专门的电机类结构体，用于实时维护目标转速与编码器反馈的实际转速。
- **控制算法实现**：为了确保运动的平顺性，控制链路中引入了速度平滑处理器。随后，数据送入 PD 闭环控制器，并经过严格的限幅处理，最终转化为控制定时器的 PWM 波输出。
- **系统级闭环验证**：在正式接入 ROS 2 之前，先移植 PS2 手柄驱动库。在主循环中读取手柄指令，结合速度幅值解析出电机目标转速。当底盘在手柄驱动下能够精准执行平移与旋转动作时，意味着从指令下发到物理执行的链路彻底走通，物理机构的可靠性得到了完备验证。

## 本章结论

环境隔离、硬件余量与底盘控制闭环并不是准备工作，而是整个机器人系统能够承载更高层智能的前提。
